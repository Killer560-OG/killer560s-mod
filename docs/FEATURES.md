# Killer560's Mod - Full Feature Descriptions

The detailed version of the feature list in the README. Keep this file up to date whenever a feature is added or changed - the public features Doc is generated from it.

> **New tab:** every feature that's new or was just changed lives in the mod menu's **New** tab first, so it's easy to find what still needs testing. Once confirmed working it moves to its normal category tab below.

**Chat**
- Translate — auto-translates your chat messages into another language before sending
- Auto Correct — fixes common typos before you send
- Command Auto Correct — optional: fixes typos in command names you type ("/wardorbe" → "/wardrobe") against the server's real command list, never touching arguments
- Chat Emotes — shortcuts that turn into fun chat emotes
- Click Translate — click a chat message to see it translated
- Copy Chat — Shift+Click a message to copy the whole thing, or Shift+Right-Click to copy just one line of it
- Auto Meow — random cat noises
- Cringe — random one-liner messages for fun
- Spotify Mod — posts the lyrics of whatever you're playing on Spotify into chat, synced to the song. **No setup and nothing to configure**: open the Spotify desktop app and play something. It reads the app on your own PC directly — no account, no API key, no website, no login, and no source to pick. Only the artist and title ever leave the machine, to lrclib.net for the lyrics. There is no timing offset either: the app reports a track change instantly and the lyric clock stops while you are paused. Skipping forward inside a track is the one thing it cannot follow, because the app does not report your position. While an ad plays it says you are listening to an ad rather than leaving the previous song's last line up. Pick the chat it posts to, full lyrics or just the song title, and a profanity filter. Windows only
- Mod Chat — a genuinely private chat channel between mod users. Messages travel over the mod's own relay server rather than Hypixel's party or guild chat, so players who don't run the mod never see them. Send with `/killer560 chat <message>`; the tab shows who else from your party is connected. Falls back to nothing if the relay is unreachable — it will never quietly post your message in public chat
- Voice To Text — hold a push-to-talk key, speak, release to send the transcription to chat. Fully offline (Vosk); on first use it downloads the Vosk engine (~26MB, checksum-verified) and a small speech model (~40MB) into the config folder, so neither is in the mod jar. Pick which microphone it records from, and which chat it goes to: party, all chat, guild, or plain. **Untested with a real microphone** - see the New tab

- Cosmetics — one tab for how players look on your screen: Supporter Names and Supporter Sizes switches for other supporters' shared looks (each on its own; both off hides everything), Share if Supporter (one toggle that shares both your display name and your own size once your account is linked as a supporter), and three dropdowns. Custom Names is the in-game name changer: your display name with a colour, a fade, or a colour of its own for each letter, a reset back to your real name, and renames for other players. Player Size has My Size and Others' Size sliders from 0.05x to 2x, each with its own reset, plus your model's width/height/thickness. Held Item is the held-item transform. The name changer never recolours or renames anything inside this mod's own menus. Everything here is local rendering only — it never touches your hitbox, collision or reach, and anything *sent* to Hypixel (party invites, friend adds) always uses your real IGN, so renaming yourself can't break being partied or friended. If a nickname collides with a real account's name, chat asks which one you meant instead of guessing. There's a reset at the bottom
- Auto Inventory Sorter — save the exact slot each item should live in as a named layout, then apply it later with a command. Layouts are one file each so you can hand one to a friend. Items are matched by their Skyblock item id rather than material, so two different items that share a vanilla material don't get confused. Your movement keys are held off while it's sorting, so you can't walk away mid-sort. **Cheat build only**
- Item Value Tooltip — adds an item's coin value to its tooltip anywhere in the game, from the same Bazaar-first/lowest-BIN price data the Croesus tools already use. Items with no known price simply get no line rather than a guess

**Hud Elements**
- GIF Player — plays a GIF (with optional audio) as a HUD overlay. Ships with a built-in dancing cat girl GIF in every install, off until you switch it on; it is listed as "Dancing Cat Girl (built-in)" and toggled like any other GIF, and your own GIFs in the folder are untouched and still show by default
- DVD — the classic bouncing DVD logo screensaver on your screen
- Video Browser — watch YouTube Shorts in a small 9:16 window pinned over Minecraft (Windows only; uses your installed Edge or Chrome in its own profile, log into YouTube once). Keybinds for show/hide, next, previous, play/pause and mute work without leaving the game. Dark / Light / System / Amber theme option. Also plays normal YouTube, TikTok, Instagram Reels, Twitch or any URL; an edit mode to drag-move and resize the window; a zoom setting; a DVD-style bouncing placement; and a YouTube comments guard so next/previous does not fire while comments are open. **Untested** - see the New tab
- Health and Mana Bars — reads Hypixel's action bar (health, mana, defence, overflow mana, and any other current/max stat it shows with its own icon) and draws your own bars and text from it. Turn on Stat Bars, then use the four dropdowns inside. **Hide**: the vanilla health/absorption/mount/regen/armour/hunger bars, the hearts/hunger/armour/air set that only acts while Stat Bars is on (with Unhide Hearts In Rift), Hypixel's own stat text on the action bar (only the stat numbers go - "5/7 Secrets" or an ability name on the same line stays), and the XP bar with its level. **Bars**: Health (health past max shows in an absorption colour), Mana, Defence (shown as damage reduction, defence / (defence + 100)) and Other Resource, each with its own colour, plus shared width, height, background and an on/off number on the bar. **Text**: Health, Mana, Overflow Mana, Intelligence (worked out from max mana, which is 100 + Intelligence), Defence, Effective Health (health x (1 + defence / 100)) and Other Resource, each with its own colour, plus a text shadow toggle. **Classic Display**: the original one-line HP/MP/DEF readout. Every bar and text is its own HUD element, moved in the HUD editor and scaled from its own slider or the editor. True Defence and Vitality are not offered: Hypixel never puts them on the action bar, only in the /stats menu

**Helpers**
- Performance HUD — your real ping to the server (read from the tab list, not a local estimate) and the server's TPS. Previously called Lag Display; the "server lag" readout was replaced with a real TPS figure and the text bar at the bottom removed
- Quiver Display — shows the real "Arrows Remaining" count from any real arrow/quiver item anywhere in your inventory or off hand
- Experimentation Table Solver — solves Chronomatron, Ultrasequencer, and Superpairs by highlighting the answer: you click, it just shows you where. It is its own setting rather than a mode, so you can run it on its own. The **cheat** build adds a separate Auto E-Table section that clicks for you, independent of the solver - either, both or neither can be on; its auto-swap to your best Guardian pet before a run is on by default - see [Which jar do I download?](#installing) below.
- Experimentation Table Profit Tracker — logs every claimed experiment (game, clicks, rewards, XP, bits) with coin values and running totals, plus a max-clicks chat notice whether you are using the solver, the Auto E-Table, or both. On by default
- Storage Overlay — see the contents of every Ender Chest page and Backpack live, right alongside your open inventory
- Bug Report — `/killer560 bugreport` builds one zip you can drag straight into Discord: your latest log, every one of the mod's config files, and a report of your mod/Minecraft/loader versions, which jar you are running, your OS, Java and memory, and every mod you have loaded. **Credentials are stripped before anything goes in.** Your session-login and account-proxy files are left out entirely rather than redacted, and in everything else any value whose name looks like a token, secret, password, auth, session or cookie is replaced with [redacted] - verified against a file containing six different fake credentials, all six removed, with keybinds and normal settings left untouched. Log lines are scrubbed the same way. It tells you where the zip is and opens the folder
- Dungeon Sim — **work in progress, not part of a release yet.** A clear-practice dungeon you join from a Dungeon Sim button on the Multiplayer screen. It connects to nothing: it opens a flat local world this mod owns, and everything in it is client side. The button opens a chooser - load a previous run, create a new map, load a single room, or All Rooms (every captured room in one line, for writing routes). The generator takes puzzle count and rooms-to-blood; the room picker has a search box and filters for shape, puzzles and Auto Routes (see Dungeon Sim Route Filter). Inside: etherwarp, Wither Impact, Tactical Insertion, Spirit Sceptre, Superboom, Dungeon Breaker and the Terminator (three arrows, and Salvation piercing five after three hits), all reimplemented locally, all swinging at Hypixel's 100 Attack Speed baseline. Mage is the only class, with the left-click beam, which has ZERO pierce - it kills the nearest thing you are looking at and nothing else. Mobs have 1 HP and never move, so a route is timed against the route rather than against where a mob wandered; starred ones carry the same name-tag stand Hypixel gives them, so Mob ESP and everything like it works unchanged. Fels sit as motionless skulls and wake into an upside-down enderman when you approach. Wither doors take a key, become barriers, then clear. One mimic per map. The sim used to outline every chest that could have been it, and that outline is gone: because every placed secret chest is a mimic candidate, it amounted to highlighting every secret on the floor whether or not Secret Waypoints was switched on. The sim has no highlighter of its own now - Secret Waypoints is the only thing that draws secrets in there, under exactly the setting that draws them on Hypixel. Score follows Catacombs: one point per crypt to five, two for the mimic, Paul's EZPZ, and bats counting as secrets. `/speed <n>` sets speed on the Hypixel scale. `/simpuzzle <name>` builds a puzzle to drill. A five-second countdown holds you at the start of a full run. **State, 2026-10-01:** secrets come from the room database and land inside their rooms (asserted by a scenario that builds a floor and checks every chest). A Catacombs sidebar is put up on the sim's own integrated server, so the floor, the secret count, the keys and the room you are standing in read as they do on Hypixel. Rooms are rotated now: each capture's own quarter turn is recovered from its roof marker and its secrets, so a rotated room still puts its secrets in the right corner. **The eleven puzzle rooms are bound to their real geometry rather than to invented arenas** - the room's own levers, buttons, pads, lanterns, ice and boulders, found by scoring each puzzle's coordinates against the pasted blocks at all four rotations and refusing to arm a room they are not in. That means your own puzzle solvers and auto-puzzles work in there against the same data they use on Hypixel; `docs/SIM.md` records what each one was measured against. **Not done:** mobs (the captures hold no mob positions); a handful of rooms have imperfect captures (Balcony, Catwalk, Purple Flags); and none of it is tuned against a real floor yet
- Dungeon Sim Teleports — **work in progress, sim only.** Two ways of getting around inside the dungeon sim, and neither command exists anywhere else: both are gated so that outside the sim they do not run, do not tab-complete and do not shadow whatever Hypixel does with those names. `/goto <room>` (also `/tpto <room>`) teleports you into a room by name, and the name tab-completes against the rooms on the floor you are standing in rather than against the whole 135-room library - so it can only ever offer you somewhere you can actually go. The argument is greedy, because room names have spaces in them ("Higher Blaze", "Lava Ravine"), and completion matches a prefix first and then any substring, so "blaze" offers both halves of the blaze pair; a name that matches two different rooms is refused rather than guessed. Where you land is not a fixed offset: it is the same search the builder already uses when it drops you into a single room, scanning the cell's centre column for a solid block with two blocks of air on it, which is the only definition of "somewhere you can stand" this mod has. `/c <blocks>` clips you that many blocks along the direction you are looking, and a negative number goes backwards; it goes through whatever is in the way, which is the point of a clip in a practice world, and the height is clamped into the world so a clip straight down cannot drop you under the void. Both write your position directly, which this mod never does anywhere else and must never do on Hypixel - the sim's "server" is the client's own integrated server, no packet leaves the machine, and the same gate that guards every other sim ability (a singleplayer world AND no connected server) is what makes that true rather than hoped for
- Dungeon Sim Route Filter — **work in progress, sim only.** Find the rooms that still need Auto Routes without scrolling the whole list. The Load a Room picker (also what Change Room opens) has a Routes button beside the shape and Puzzles filters that cycles **Routes: All**, **No routes** and **Has routes**, and it remembers your choice across restarts. Every room row shows its Auto Routes at a glance on the right: a green node count when it has a route, a grey "no routes" when it has none. The No routes and Has routes views only list rooms worth routing - puzzle rooms, Blood, Entrance, Fairy and any room with 0 secrets are left out (that also drops the miniboss rooms, which have no secrets). While you are in a room loaded on its own, the pause menu has **Next room with no routes** under Change Room: it loads the next eligible room in the picker's (alphabetical) order that has no route, wrapping round at the end, so pressing it again keeps walking the list; when no other room is left without a route the button and chat say so and nothing loads. `/simbuild noroutes` does the same from chat. "Has a route" means at least one node in your Auto Routes file for that room - the same file and the same room names Auto Routes plays from, and one route covers every rotation of a room
- Map Designer — draw a floor by hand instead of generating one, from the "Design the map..." row on the Create a New Map page. The grid on the left is the dungeon's own 6x6 of room slots; the list on the right is every room in the library that can actually be pasted, searchable, with its kind, shape and secret count, and coloured by room type the way the live map colours it. Click a room then a cell to place it, right-click a cell to take it out. Only the doors the build will really cut are drawn - a gap between two rooms that stays walled shows as a wall - and they are coloured the way the dungeon map colours them: a narrow opening for an ordinary doorway, the blood colour for the blood door, the entrance colour for the entrance gate, and the wither colour with an amber outline for a wither door. The sim builds no wither doors, so the doors a real Hypixel floor would have as wither doors - every door on the room path from the entrance to blood, except the entrance gate and the blood door - are drawn that way too, here and on the sim's live map (with a single outline there, and "A wither door on a real floor" in the interactive map's tooltip); never on a real Hypixel map. Room names are fitted to the room exactly as the dungeon map fits them, one word a line and scaled down until they fit, so a 1x1 shows its whole name rather than a truncated one. Every generated floor, from Generate here or from the random generator, holds one trap room (Old Trap or New Trap). Fill drops a random room into every free cell as a starting point. A room whose footprint would run off the grid or over a neighbour is refused rather than squeezed in, so a drawing always builds the floor it shows. Save and Load keep named designs in `killer560smod-simmaps.json`, which survive a restart like any other setting; a saved design that names a room you no longer have loads the rest and says how many it dropped. Play hands the placements to exactly the code path the random generator ends in, so a floor you drew and a floor the mod invented are built identically and differ only in which rooms went where
- Auto Debuff — **cheat build only.** The M7 dragon debuff, on the dragon the split says is yours: prefire Last Breath at the spawn box, stop in time to get the Ice Spray Wand in hand, jump ~300ms out, spray on the spawn tick, then swap and hit it. Healer and Tank use Flay (Soul Whip or Flaming Flay, either tier) at its real 0.5s cooldown; Mage melees instead, preferring Dark Claymore, then Midas' Sword, then a Hyperion with Chimera, then one with Ultimate Wise, with its own Mage Melee After toggle. Separate on/off per class for Mage, Healer and Tank - Archer and Berserker are never touched and have no setting. Stops once the dragon leaves the killbox. M7 only, since F7 has no Phase 5. The jump and spray have no slack between them, so the lead is ping-aware by default. **Walking is not implemented yet**: it does not path to the split, does not chase the dragon for the melee classes, and does not walk back on a death - so today you position yourself and it does the timed sequence
- Update Notice — tells you once, the first time you join a world each launch, if a newer release of the mod exists, with the version you are on and a link. It is a single check on startup, not constant background checking, and it stays silent if it cannot reach GitHub - so playing offline or behind a filter gets you nothing rather than an error you can't act on. Only full releases count; pre-releases and the Latest Dev Build are ignored. On by default (the one exception to new features shipping off, because the notice exists to catch people running a months-old jar), and turned off with Notify Me Of Updates on the Home tab, where Check For Updates still works on demand
- Screenshot Copy — automatically copies a screenshot to your clipboard the moment you take it
- No Fire — removes the on-screen fire overlay so burning doesn't block your view mid-fight
- Discord Rich Presence — shows "Playing Killer560's Mod" on your Discord profile, with your island/area, dungeon floor and boss phase, and an elapsed timer. Off by default; a Hide Details mode shows only the mod name
- Object Hider — client-side render suppressors for M7/F7: healer fairy, power orbs (with a keep-nearby radius), soulweaver skulls, archer bone meal, sheep, wither cloak creepers, shield hearts, grounded arrows, blindness, death animations, block-break/explosion/smoke particles, dying P5 dragons, the Wither King model, boss damage splashes, and a Clean End mode. Nothing is removed from the world — it only stops rendering. The vanilla health/armour/hunger bar hides live under Health and Mana Bars, the chat-line hides under Hide Chat Messages in the Chat category, and Hide Players has its own section
- Ability Cooldowns — automatic cooldown HUD: detects the ability you used (its sound, the mana action-bar line, or chat) and counts down the real cooldown from a 41-item table ported from SkyHanni, with a dungeon-only filter and a click window so a teammate's ability can't start your timer
- Goldor Frenzy Timer — a HUD countdown to Goldor's 3-second P3 damage tick, plus the Storm-to-Goldor gap and an optional cumulative P3 timer

**Dungeon**
- RNG Meter — tracks your Hypixel Skyblock RNG/pity progress on dungeon floors
- Chest Profit — shows the value of every reward, the cost, and the profit next to any open dungeon reward chest (end-of-run room or Croesus), and in a Croesus run view lists every chest's profit with the best one highlighted green. Uses the RNG Meter's live Bazaar/AH prices. On by default
- Dungeon Profit Tracker — `/croesus` opens the profit screen, rebuilt 2026-09-28 to the layout killer560 asked for. **Overview**: Net Profit, Gross Value and Chest Cost as headline cards, a Rare Drops list, and a net-per-run graph with Session/Overall and a floor filter, plus the most recent chest. **By Floor**: session and all-time totals per floor. **Loot Log**: every item, how many, which floors and which runs. It added no new tracking - the log already stored per-floor totals, a per-item index and every claim's cost, value and profit, which is exactly what the concept needed. The cards and the graph live in a shared place so the same screen can serve other skills later. On by default
- Auto Croesus — **cheat build only.** Press the Start Croesus button drawn over an open Croesus menu and it opens each unopened run and claims its single most profitable chest if it clears your Min Profit, with random Min/Max click delays; optionally spends a real Dungeon Chest Key on a second chest once it clears a threshold you choose - a set profit number, or the key's own live Bazaar insta-buy or buy-offer price (falls back to the set number until that price loads) - and optionally spends a Kismet Feather to reroll a poor Bedrock chest; skips anything below the minimum, and stops on any unexpected screen or key press while running (close the menu to stop)
- Leap Message — sends a message when you leap to someone in dungeons
- Leap Order — pick the class you're playing, then place your party's names in the 4 leap menu spots; each class keeps its own layout, and the custom leap menu uses the one for the class the tab list says you're on
- Auto Routes — **cheat build only, work in progress — not part of the current release.** Record a route through a dungeon room (`/ar start record`) and play it back when you etherwarp onto its start node. Recording captures your actual path; playback follows it rather than replaying key presses blind, so a lag spike doesn't desync the rest of the route, and every etherwarp / item use / block break waits for real confirmation before moving on. `/ar add` takes exactly six types - `boom`, `breaker`, `ew` (or `etherwarp`), `use`, `walk` and `path` - and after the type only `start` and `await:<number>` (wait for that many secrets first; `await:x` or a bare `await` is refused, and so is anything else). A node goes on the centre of the block you stand in - whole blocks, not AP3's half-block grid - with the height kept at your feet; recording places its nodes the same way. Nodes saved on the old half-block grid keep working where they are, and land on a block centre the next time the editor moves them. A node you add fires straight away, as if you had just walked onto it: `/ar add ew` warps you the moment the chat closes (the first tick no screen is open), the rest of the route carries on from it as it would from any node - including the landing re-fire, so adding the second of two etherwarps aimed at each other starts the bounce - and it fires even with Start From Start Node Only on. If you step off it before the chat closes it does not fire, and while a route is already running it only latches as before. It is still one `/ar undo` step. On Hypixel it sends exactly what walking onto the node sends. A `start` node goes off the moment you step onto it, even mid-stride with W held - keys you were already holding are overridden while a node runs and only a fresh press counts as taking over - and it is the node the Interactive Map warps you to. Start nodes draw filled in, in every render style. On a route built with `/ar add` a walk node sprints the way you were facing when you placed it, until the next node fires, you take the keys or the mouse back, or you run into something. Mouse clicks never stop a route, and no longer skip an await either. Command nodes in a routes file always run (the Allow Command Nodes switch is gone). Each `/ar` command has an assignable keybind; Start and Stop Recording have theirs right under their buttons, the rest are in a Keybinds dropdown. The settings tab runs: the Auto Routes switch (full width), Mode beside Start From Start Node Only, Open Routes Folder beside Reload Routes, then Render Style (style, node numbers, thickness, height), Recording (Start / Stop with their keys under them), and the Colours and Keybinds dropdowns last, Colours directly above Keybinds - every row in even half-width columns, as AP3's tab is. The per-room node list is gone from the menu; `/ar list`, `/ar delete`, `/ar undo` and `/ar clear` do all of it. In the Filled render style each node is drawn one block lower, inside the block it was placed on top of (only the drawing moves - where it triggers is unchanged; Box and Cylinder draw where they always did). In the Cylinder style a start node's fill is a cylinder between its two rings, not a box poking out past them. `/ar edit db` still picks a breaker's blocks. `/autoroutes` is the same command as `/ar` in every form, with the same tab completion. `/ar edit <n>` opens a node editor, AP3's `/ap3 edit` for routes: the node's position in world coordinates (X, Y and Z on one row with whole-block nudge buttons under them, each landing on a block centre like a placed node; a box you leave alone keeps the stored value exactly), yaw and pitch for etherwarp, use and walk nodes, the use item, the type (the five `/ar add` types), Start Node on or off (only one per room; saving moves it off the old one), an Await Secrets dropdown from None to 4, and for a breaker Pick Blocks (saves, then breaker edit mode on that node) and Clear Blocks, plus Look from me and Item from hand, with Save, a two-press Delete and Cancel in one row at the bottom; each section (Position, Aim, Item, Node, Breaker) sits under a small heading, and Position from me is gone. Go To is the full-width amber button at the top of the editor. Go To saves, closes the editor and etherwarps you to the node with the Interactive Map's own pathfinder (the same call the map uses, so it plans with whatever the map plans with); when you arrive, edit mode turns on and the node is latched, so it does not fire under you, even after edit mode goes off, until you step off it. If there is no etherwarpable block at or near the node, or the pathfinder finds no path, it says so in chat and edit mode stays off. Go To is refused while recording or while another Interactive Map warp is running. On Hypixel Go To sends exactly what an Interactive Map warp sends - the same etherwarps, rotations and sneaks - and nothing else; the editor itself sends nothing. Every save from the editor is one undo step, and `/ar redo` (and its keybind) re-applies whatever `/ar undo` last took back, including a delete; any new change clears the redo history. Routes live in one shareable, hand-editable JSON with an Open Routes Folder button and `/ar reload`. A `USE_ITEM` node matches on the item, not the exact id: stars, fragging and reforges were already ignored, and the four wither blades (Hyperion, Astraea, Scylla, Valkyrie), Spirit Leap/Infinileap and Superboom/Infinityboom now count as one item each. Aspect of the End, Aspect of the Void and the Etherwarp Conduit count as one too: they share the same 8-block Instant Transmission and the range comes from the Transmission Tuners on the individual item, up to four, so a fully tuned one of any of them goes 12. Nodes are numbered per room the way AP3 numbers its chains: 1, 2, 3 in the order they were added, drawn over each node (Show Node Numbers, on by default; nodes on the same tile lift their labels apart), and renumbered the moment one goes, so the old #3 reads #2. `/ar delete <n>` and `/ar remove <n>` are the same command and take that number; with no number they delete the node you stand clearly nearest (within 3 blocks, and every other node at least a block further), and say so instead when it is ambiguous. `/ar undo` takes back the last add, delete, breaker-block edit or `/ar clear`, whichever room it was in, as many steps back as you like (the history lasts until the game closes or `/ar reload`); with nothing left to undo it deletes the last node of the room you stand in, as AP3's does. `/ar stop` ends a running route. On a route built with `/ar add`, a teleport that lands you in a node fires that node, even one earlier in the route or the one you just left: two etherwarps aimed at each other bounce you back and forth until you press a movement key or `/ar stop` (or its key). Each bounce still waits for the server to confirm the landing. Several nodes on the same tile (the same snapped spot, the way `/ar add` places them when you add more than one without moving, with the feet in the same block) all fire, one after another, each waiting for the one before it to finish: dungeon breaker, then superboom, use, command, rotate, unsneak, etherwarp and walk last, so whatever moves you goes after everything that needs you standing still. Within one type the `start` node goes first, then by number, and a node's `await:<n>` waits before its own turn. The stack runs as one unit: where its last node puts you, the landing re-fire above applies to whatever node or stack you land in; a movement key, mouse turn or `/ar stop` ends the rest of it and the tile stays latched until you step off; if one node fails (the etherwarp does not land, the breaker has no charges) the rest of that stack does not run and the usual stop message says why. A node that already went off as part of a stack is not fired again when the route reaches its own number. Stacked labels lift apart with the lowest one firing first. Numbering, delete and undo are unchanged. On Hypixel nothing new is sent: each node in a stack sends exactly the packets it sends on its own, with the usual interact delay between them. Every node acts on the tick it fires: the hotbar swap, the sneak and the aim are asked for together, so an etherwarp that needs to start sneaking uses one tick later (its sneak goes out in the firing tick's input packet, ahead of the use), an etherwarp you are already sneaking for, a use, a superboom, a command, a rotate, an unsneak and a walk all go on the firing tick itself, and a dungeon breaker breaks on the firing tick, right behind the swap: with Breaker Aura's Multi Break on (its default) every one of its blocks that is loaded, solid and within reach goes out on that tick, as many as the breaker has charges, followed by one swing - the same burst Breaker Aura sends; with Multi Break off it breaks one block per interact-delay tick as before. A node never asks for more blocks than the charges the breaker showed when it fired. A swap no longer costs a tick, and no longer sends the same held-item packet twice. Legit mode still waits for its camera turn, an await still waits for its secrets, and every teleport still waits for the server to confirm the landing. Each node writes an `[AutoRoutes] Node #n TYPE acted N tick(s) after firing` line to the log. Sneak is held between etherwarps: after every node the route looks at the node that fires next (the rest of the stack, the node a teleport landed you in, or the next in order) and, if it is an etherwarp, keeps sneak down - or starts it, when that etherwarp fires where you stand - so the server already has the sneak and the etherwarp uses on its firing tick (0 ticks instead of 1; two etherwarps aimed at each other went from 2 ticks per warp from firing to the landing down to 1). A walk node lets go (the walk sprints), and so do an unsneak node, the route ending or stopping however it stops, and a use-item node, which waits for the server to have the sneak up first because sneaking changes what a right click does (an AOTV would etherwarp, a chest would not open). A superboom, breaker, rotate or command node in between keeps it held. On a route built with `/ar add` the sneak stays down while you walk to the next etherwarp yourself, so you walk there at sneak speed; on a recorded route the recording's own sneak drives the walk between nodes. A `[AutoRoutes] Sneak held/released after node #n` line says when it changes. On Hypixel holding sneak is just a held key: one input packet with shift down when it starts and one with shift up when it ends, nothing in between. **Path nodes** (`/ar add path`, also with `start` and `await:<n>`, and in `/ar edit <n>`): path nodes pair up in number order - the room's 1st path node with its 2nd, the 3rd with the 4th - and the first of a pair etherwarps him to the second along a chain of warps planned by the Interactive Map's own floor planner (the same call a map press makes). The chain is planned ONCE - when the second node of the pair is added, or the first time the pair fires if it had no plan yet - and saved on the first node in the routes file, room-relative like every node, so it replays the same at any rotation and on Hypixel; playback flies the saved warps and never plans again. It is planned again only when either node of the pair moves or goes (an edit, a delete, an undo or redo), or when Re-plan Path is pressed in that node's editor, which also shows how many warps are saved. Each warp is an etherwarp exactly like an `ew` node's - the same sneak, held between warps, and the same landing check - and a path fires in the etherwarp slot of a stacked tile. The second node of a pair is the arrival: landing in it fires it (it does nothing itself), its await and whatever is stacked on its tile. A first path node with no partner yet says so in chat and does nothing. **Missing landing block**: before any etherwarp the route makes (an `ew` node or one warp of a path), if the block it lands on is not there in his world - air, broken, not yet placed - nothing is sent: the route holds where it is with sneak still down, says once in chat which block it is waiting for, and warps on the tick the block is back; after 60 seconds it stops with a message. **Awaits and chests**: a node waiting on `await:<n>` keeps waiting while a screen is open - a secret chest's own window is usually the secret it is waiting for - and fires on the first tick the screen is closed; any other screen still stops the route. While a node waits on its await the held etherwarp sneak is let go (a sneaking right click with an item in hand uses the item instead of opening the chest - with the etherwarp item that is a warp), and it comes back when the node fires, so an etherwarp after an await uses one tick after it is met. If the chest window arrives a tick after the secret count, the node starts over once it closes. Breaker edit mode (/ar edit db) now takes its right clicks ahead of every other click handler, so a held Superboom or AOTV can no longer fire on a pick. The routes file keeps six decimals for every position, look, landing and saved path warp, and a node is rounded to exactly that the moment it is placed, recorded, edited or planned, so it behaves the same before and after /ar reload. **Run While Map Open** (off by default, under Mode): with it on, the Interactive Map's screen no longer holds Auto Routes back - nodes fire when you walk or land on them and a running route keeps running, sneak and stacks included, while the map is merely open. A warp the map itself is making still stops a route and takes over, as before, and every other screen (a chest, your inventory, chat, the node editor) still pauses it. **AP3 - automated F7/M7 Phase 3 (cheat build only)**

AP3 walks, aligns, leaps, uses items and times you through the F7/M7 Goldor phase (P3, sections S1-S4) along a route of *nodes* you place yourself. It only ever presses real keys - W/A/S/D, sneak, sprint, jump - and turns your real view, exactly like a player would; it never writes your position or velocity, and it stops the moment the server corrects your position (two corrections in ten seconds switch AP3 off). Use it on your own risk - it is automation and against Hypixel's rules.

*How it runs*
- Every node has a small trigger box (0.5 or 1 block by default, or any size with w<n> l<n>). Walking INTO a box fires that node; the ones you are already standing in do not fire again until you leave and come back.
- Nodes fire one per tick in a fixed priority: Stopwatch, Stop, Align/Axis Align/Fast Align, Look, Terminal, Leap Counter, Walk/Run, Jump/Edge/Block, Boom, Leap. A queued node waits for the one before it.
- AP3 knows which section you're in and only arms that section's nodes. Force Dungeon (in the tab) lets you place and test nodes anywhere, and Test Mode runs nodes without waiting for terminals or teammates.
- Freeze View (Freecam): while AP3 turns your real yaw for an align or a walk, your screen keeps the view you had and your mouse moves only the view. Your model in F5 and the server see the real angle.
- Moving yourself (WASD/space) stops AP3 at once - except inside an Align, which takes your keys over until it has landed.

*Placing nodes* - `/ap3 add <type> [modifiers]`, or a keybind for each type
- Nodes snap to the nearest half block (a block centre, or the line between two or four blocks) unless you add `precise`; the height is your exact feet height, so nodes on carpet or slabs sit on top.
- The angle recorded is where you are looking (or where your free camera looks while Freeze State is on).
- `/ap3 list`, `/ap3 undo`, `/ap3 redo`, `/ap3 delete [n]`, `/ap3 replace <n>`, `/ap3 clear`, `/ap3 reload`, `/ap3 stop`, `/ap3 testmode`. Routes are saved per config file in the killer560smod-ap3 folder; Choose AP3 Config switches between them. `/ap3 undo` now takes back the last add, delete, move, re-place, editor change or clear, whatever area it was in and as many steps back as you like (until the game closes or `/ap3 reload`) - it used to remember only the last added node; with nothing left it still deletes the last node of the chain you stand in. `/ap3 redo` (and its keybind) re-applies what undo took back; any new change clears the redo history. Sliders in the AP3 tab are not undo steps.

*Node types*
- **Align** - lands you on the node's point to within 0.001 of a block, typically in 6-9 ticks from entering at speed. It plans the fastest landing each tick, mixing turning your real yaw, every key combination and sneak taps, and only counts as done once you have actually stopped.
- **Axis Align** - for a node placed against a wall: walks you into the wall (which pins that coordinate exactly), then holds one key into the wall at a small angle that steers you along it until you stop exactly on the point, without ever pulling off the wall.
- **Fast Align** (`/ap3 add fastalign`) - an align built only for speed: each tick it plans the fewest ticks until you are standing still on the point (within 0.001), combining a camera turn to any angle with any key combo and sneak, so it brakes with a sneaking tap against your momentum instead of coasting to a stop. In testing it finishes in 3 ticks about 83% of the time and never takes more than 4, where the regular Align takes 8-11 (up to 16).
- **Path** (`/ap3 add path [start|end] [<step>]`) - the route optimiser. Each Path node is a numbered step: `/ap3 add path 2` or `/ap3 add path two`, and with no number it takes the lowest one still free (place 1 and 3, the next one becomes 2). Nodes that SHARE a number are one step to be done in any order - put both levers on step 2 and it works out whether to take them one after the other or, if their boxes overlap, run between them and take both on the same tick. Place Path nodes in order and it works out the fastest way to hit every one of them, from the first to the last, without skipping any: it searches the real movement model a tick at a time (key combination, yaw and jump) and plays the answer back through the same key-writing every other node uses. Modifiers: `exact` (keep the block relationship you placed it with - the hitbox covers the same blocks, on or off an edge - rather than a meaningless decimal match), `speed:<min>-<max>` (the speed window it must cross at, blocks per tick; `speed:0.4-` at least, `speed:-0.3` at most), `dir:<deg>` with `dirtol:<deg>` (the heading it must be travelling at), and `term` (stop here, wait for a terminal to be closed, and plan the next leg from rest - a term costs you all your speed, so there is no point arriving fast). A Block node's block is understood too: the spot it will place is treated as floor for two ticks of running (a bottom slab at most), and the route never places it itself. Whether it jumps is worked out, not assumed: the air only accelerates you at a flat 0.026 no matter your speed stat, so bunny-hopping wins at vanilla speed and loses badly at 550. The world is read into a snapshot of its real collision boxes each time it plans, and every tick of the search sweeps your 0.6x1.8 hitbox against them the way the game does - one axis at a time, with the same step-up search - so stairs, slabs and ledges are planned on what actually happens rather than on a height profile. That is what lets a route run up a staircase: it climbs half a block a tick and knows that each riser takes your speed with it, so it plans around the climb instead of expecting to keep sprinting through it. Blocks Breaker Aura is going to break count as air, lava is somewhere the route may not go, and the plan is drawn through the world at the heights it will really run at. Mark the two ends of a route with `start` and `end`: one section can then hold several separate routes and each knows where it stops, instead of running on into the next one. To extend a route, delete its `end` node and place a new one further along. A chain with no `end` marked anywhere behaves as it always did and runs to the last Path node in it. Each way of arriving at a route is searched ONCE. The first time you run it from a given spot the search is allowed to think hard - seconds, a wide beam, several differently-shaped searches, and a longer second attempt if the first ran out of clock - and the answer goes in the config folder; arrive that way again and it loads instantly and runs exactly the same, because a saved plan is never replaced once it exists. Arrive somewhere quite different and it searches once more and remembers that approach too. What it will not do is hand back a plan built somewhere else: a plan is a fixed schedule of key presses, and replayed from the wrong place it does not go to the node, it repeats the movements that went to the node from another one. `/ap3 regenerate` forgets the plans for the route you are standing in, so the next run searches again. When a route is too tangled to plan in one piece - a gap, then a ledge, then a climb - it is cut up and planned a piece at a time, landing on each cut point, because a route that pauses is worth more than a route that does not exist. A route that never leaves the ground always wins over one that jumps, however the tick counts compare, and running into the world costs the search real ticks so it will coast, walk or take off early to keep a clean line - though a collision that gains height is how you climb a step and is charged nothing.
- **No Go** (`/ap3 add nogo`) - a GHOST BLOCK: solid to the route planner, absent from the world. It never fires as a node and nothing is ever placed or sent; it simply tells the route there is a block here even though there is not, so the route can stand on it, step up it, be stopped by it and jump off it. Use it to build the geometry a movement needs when the room does not provide it. A full block on the node's own level, sized by the node's box.
- **Term Aura** (`/ap3 add termaura`) - steps on it and clicks a terminal in range once to open it, trying again two ticks later if nothing opened. It does not turn the Terminal Aura setting on or off - it is one pulse of it.
- **Walk / Run** - keeps you walking (or sprinting) in the direction the node was placed, until any other node fires. Your real yaw snaps so W+A / W+D (45 Degree Strafe on, the faster diagonal) or W points exactly along the walk from the first tick. On the tick a jump goes in it faces straight ahead so the sprint-jump boost follows the walk, then strafes again in the air.
- **Jump** - jumps on the next tick after you enter it (waiting up to a second for the ground). Does not end a Walk/Run.
- **Edge Jump** (`edge`) - jumps as late as the game allows when you run off a block: on the one-tick "coyote" window just after your feet leave it. Does not end a Walk/Run.
- **Block** - places a block (the held block, else a slab, else any block in your hotbar) where you were looking when you placed the node, then swaps back to what you held. The block shows on your screen at once, so you can run across ghost slabs. Does not end a Walk/Run.
- **Look** - turns your camera to the node's angle client-side only (no rotation is sent).
- **Boom** - uses a Superboom on the block along the node's angle.
- **Leap** - opens Spirit Leap and leaps to a class, a player, or your Fast Leap target. **Leap Counter** waits until that many teammates have leapt to you.
- **Terminal** - waits for the terminal you're at to be done. **Stop** - lets go of every key and waits until you've stopped.
- **Stopwatch** - the first one starts a timer, the next one stops it and prints the time. Name the starting one (`/ap3 add stopwatch s3`) and, with Send Stopwatch to Party on, the time goes to party chat as "s3 took 12.345s".

*Modifiers* (any node, after the type)
- `w<n> l<n>` (also `w.5`, `.5x.5`) - the trigger box size. `precise` - no snapping. `wait:<ms>` - hold the next node that long after this one. `close` - only fire on a left click or after a menu closes.
- `jump` / `edge` - after the node has done its part, jump (or edge-jump). `/ap3 add run edge` runs at the node's angle and jumps at the edge.

*Display*
- Node boxes with arrows (walk direction), wall markers (axis align) and look rays; labels with number, type and details; a colour per node type (or one colour for all); Show Nodes and Show Node Lines to hide them; Node Messages (None / Simple "Added #3 Walk" / Detailed, which also shows the queue).

*Freeze State* (its own red tab; never use it on Hypixel)
- `/freezestate` freezes your character in place (no movement, no gravity) while your camera stays free - handy for placing nodes at an exact angle.
- Rewind 1 Tick / Forward 1 Tick keys: rewind puts you exactly where you were one tick before your current position (Rewind Memory sets how many ticks are kept); forward predicts - the game runs exactly one real tick from where you are.
- AP3 keeps running while frozen: each forward step runs one AP3 tick, and your own keys and mouse never move the character - only the nodes do.
- On Hypixel the step keys refuse (it would teleport you - an instant ban); only a typed /rewind works there, behind a large warning.

You can move exactly what you could just see: an element is draggable if its own setting is on **and** it actually drew on screen within the last ten seconds, so the dungeon timers are editable in a dungeon and the RNG Meter ranking is editable for ten seconds after you close that menu. An element that is switched on but has not been on screen recently is still listed, dimmed, with the reason next to it - flip Show Unseen to move those too. Anything switched off in settings is not listed at all. Every element starts fully on screen at any GUI scale or window size, and opening chat never hides the HUD (real menus still do)
- HUD Scale — one slider, SkyHanni-style, that resizes every HUD element of the mod at once, from 5% to 300% in 5% steps (100% by default). It multiplies each element's own size rather than replacing it, so an element you set to 200% and then a HUD Scale of 50% draws at its original size, and goes back to 200% when the slider returns to 100%. Saved with profiles. Auto Scale (monitor) - the button under it, ON by default - also sizes everything the mod draws (every HUD element, the centre-screen popups, and all of the mod's own menus: this menu, the AP3 and Auto Routes editors, the friends list, the AH and Bazaar browsers and the rest) to your window, so it all stays the same size relative to the screen on a 1080p, 1440p or 4K monitor and at any Minecraft GUI Scale. The reference is a 2560x1440 window at GUI Scale 3, where nothing changes at all; a 1920x1080 window at GUI Scale 3 draws at 75%, a 4K one at 150%, and the button shows the factor in use. The HUD Scale slider multiplies on top. HUD positions move with it, so a layout keeps its shape on every monitor and nothing is pushed off screen. The HUD editor itself is not scaled, so it always shows elements at exactly the size and place they draw in game. Saved with profiles
- Discord Rich Presence's options sit directly on the Home tab under the Mod & HUD settings, with no dropdown to open
- The mod menu remembers your scroll position, selected tab, and search text between opens

**Profiles**
- Save your current settings as a named profile, switch between profiles, and export one to a single `.zip` file to share with a friend. To receive one, click Import Profile: it opens the import folder, and any `.zip` dropped in is imported within a couple of seconds as a new profile named after the file. Excludes real credentials (session login token, per-account proxies) and run caches - only actual feature settings travel with a profile. While a profile is loaded, every setting you change is saved into that profile too, so switching away and back keeps your changes
